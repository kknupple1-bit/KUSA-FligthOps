KUSA FlightOps 5.26.23 — Exception-Driven Takeoff Obstacle Review

Purpose
- Remove repetitive pilot obstacle acknowledgement when there is no current obstacle-related FAA NMS flag and verified OEI/second-segment climb performance is available.
- Preserve a blocking/manual-review path for exceptions.
- This revision does not claim surveyed or certified obstacle clearance.

Takeoff obstacle / NOTAM logic
1. FAA NMS obstacle-related NOTAM screen clear + OEI/second-segment climb passes:
   - Baseline obstacle gate clears automatically.
   - No separate pilot obstacle acknowledgement is required.
   - TOLD/takeoff status may proceed subject to the remaining performance, runway, NOTAM, N1, W&B and fuel gates.

2. FAA NMS obstacle-related NOTAM flag:
   - Pilot exception review is required.
   - The pilot review control is shown.
   - A no-conflict disposition may clear the exception; a conflict remains NO-GO.

3. FAA NMS obstacle-related screen unavailable:
   - Pilot exception review is required.
   - The gate remains caution/review until disposition.

4. OEI/second-segment climb data incomplete or failing:
   - A clear NOTAM screen does not substitute for climb performance.
   - Missing climb data remains pending; a failed second-segment climb remains NO-GO.

Human factors
- Pilot obstacle review is labeled "Exception Only" and hidden during normal clear-screen operations.
- The automated display states "NO OBSTACLE NOTAM FLAG • CLIMB DATA READY" when the baseline condition is satisfied.
- Wording explicitly states that the workflow is not a surveyed/certified obstacle-clearance analysis.

Build

Release-review corrections
- Unknown/not-checked obstacle screens stay pending in both Evaluate and refresh.
- Climb readiness is checked independently even after a pilot exception disposition.
- Explicit pilot conflicts remain NO-GO on refresh as well as evaluation.
- Review-required or unavailable statuses cannot turn green merely because their text contains PERFORMANCE PASS.
- Executable gate regressions replace source-text matching checks.

Pull-to-refresh
- Added an in-app touch pull-to-refresh gesture for iPhone/iPad/PWA operation.
- Pulling down from the top now refreshes the active mission's live operational data using the same controlled refresh path as the existing TOLD refresh action.
- Current mission/draft state is saved before refresh.
- The gesture shows Pull / Release / Refreshing / Complete feedback.
- Offline use does not falsely claim a live refresh; local calculations remain available and the indicator reports that live refresh is unavailable.
- If no mission is active, the gesture falls back to a normal page reload with refresh context preserved.


Pull-refresh release review
- A caught operational-refresh failure is returned to the gesture so it shows failure instead of completion.
- Completion wording directs the pilot to the weather/NOTAM status rather than implying all live sources are available.
- Executable gesture tests cover triggering, cancellation, offline behavior, failure, active mission refresh and inactive-page reload.
